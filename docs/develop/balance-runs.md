# Balance runs

Part of the developer docs; [README.md](../../README.md) has the code map, the commands and the checks.

To check the balance without playing, run this from the repository root:

```powershell
npm.cmd run balance
```

It plays every strategy listed in `src/balance/strategies.ts` against the real data files, with no browser, for up to 20 Turns each on seeds 1 to 1000, and prints the report. That takes about half a minute. For a quick pass, use `npm.cmd run balance -- --programs 200`. The same command always gives the same report, so two runs can be compared line by line, for example before and after changing `public/data`. The results inform tuning and don't fail anything: the only part that can fail a build is the invalid-state test in `src/balance/balanceRuns.test.ts`, which plays a few Programs on each strategy. The command also stops with an error if a plan fails validation or a Turn leaves an invalid state.

## What a balance change reaches

A balance change usually also reaches the tests of the tuned balance in `src/catalogue`, one file for each phase or post-playtest change that tuned it: `balancePhase3.test.ts`, which also holds the tests of the first Missions from before Phase 3, `balancePhase4.test.ts`, with Research Grants, the rover and a productive Program in `balancePhase4Rover.test.ts`, `balancePhase6.test.ts`, `balancePhase7.test.ts`, `balanceBaseFunding.test.ts`, for base funding since the Phase 7 playtest, and `balancePhase8.test.ts`, with the fuel plant, habitat and Mars lab in `balancePhase8Base.test.ts` so that the two play at the same time. All but Phase 3 test a strategy's means over many Programs, which they get from `src/testing/playedStrategies.ts`, so changing a strategy can break them too. It also reaches the current playtest guide's known seeds in `src/catalogue/playtestSeedsPhase8.test.ts`, the current guide in `docs/playtest`, and `src/balance/strategies.ts` if a strategy stops coping. And it reaches `e2e`: browser tests play with the real data files, so money, Public Support and Science figures in them can change with tuning, and a seed found in `e2e/seeds.ts` can change too. Rule tests in `src/simulation` use the test catalogue, so tuning doesn't touch them.

## The report and its strategies

The report explains its own tables: a legend at the top covers the summary and Turn table columns, each section opens with what it counts, and each strategy's section starts with what that strategy does. Its Coming Home section says how the report decides when a Program keeps itself going, which is `keepsItselfGoingFrom` in `src/balance/comingHomeReport.ts`, also used by the tests of the tuned balance. The report is put together in `src/balance/report.ts`, with its Technology section in `technologyReport.ts`, its Crew section in `crewReport.ts`, its Coming Home section in `comingHomeReport.ts`, and the lines of each strategy's section on what a base at Mars did and what came home in `baseReport.ts`.

Strategies are simple on purpose, so a difference between two of them is only a rough guide to what a thoughtful player would find. To judge one choice, compare two strategies that differ only in it:

- The ones named `steady:` each differ from `steady: Soil analysis` in one choice. For a Decision Point answer, compare `steady: Soil analysis` with `steady: carry on through storms`.
- Programs that develop tend to be the ones already doing well, so judge a Development by whole strategies, such as `steady: develop the Endurance Rover when rich` against `steady: Soil analysis`, not by the Technology section's split by whether a Program started one.
- Each strategy that varies another starts its description by naming it ("As …", or "The same" for the one listed just before it), so compare those two. Descriptions are passed to `playStyle` in `steadyStrategies.ts` and `bigProgramStrategies.ts`, and the report prints each at the top of its strategy's section. Crew play is in `src/balance/crewPlay.ts`.
- `playProgram.ts` checks every Turn for invalid states: general ones in `invalidStates.ts`, and one file per subject: `invalidCrew.ts` for Crew, `invalidHomecomings.ts` for Crew coming home, `invalidPropellant.ts` for ascent propellant, `invalidFetching.ts` for fetching Crew with a return vehicle, `invalidHabitats.ts` for habitats, `invalidLabs.ts` for Mars labs and `invalidSamples.ts` for samples.

The last strategy, `tutorial: build a Base and land Crew there`, is the tutorial's advice from `src/tutorial`, followed every Turn. Its section ends with how often it reached its goal, Crew at a Landing Site where a fuel plant, a Habitat and a Mars lab operate, and by which Turn, and how often it judged a Program unable to reach it ("Can't recover"), with how many of those went on to reach the goal anyway, as it plays on after that. A strategy reports these lines when it has a `goal`, and they are worked out in `goalReport.ts`. `src/catalogue/balanceTutorial.test.ts` holds that it reaches the goal in most Programs and that Can't recover rarely ends one that would have.

The strategies named `cautious` and `bold` are the yardsticks for how the game rewards risk: `src/catalogue/balanceBaseFunding.test.ts` holds that Cautious is rarely cancelled and recovers from a failed first Mission, and that Bold is cancelled many times as often, about three Programs in ten since the Bailout refunds its first lost gamble, but is far ahead when it isn't. The play styles they and the others are built from are in `src/balance/styleParts.ts`.

To add a strategy, add an object to the `strategies` list in `strategies.ts`, or to `steadyStrategies.ts` or `bigProgramStrategies.ts` for one named `steady:` or `big Program:`, with no other change. The one exception is `steady: Survey once`, which the report has always listed after the `big Program:` ones, so `steadyStrategies.ts` exports it on its own, as `steadySurveyOnce`, and `strategies.ts` places it there. Its `plan(view, tools)` sees what a player sees: the `ProgramView`, the previews and `tools.problemsWith(plan)`. It returns a `TurnPlan`, which must pass validation, so it has to cope with shortages of money and with what's on offer changing. It can also have an `answer(decisionPoint, view)` for what it does at a Decision Point, and takes the first choice offered if it hasn't, and a `takeBailout(view)` for whether it takes the Bailout on offer after a lost Mission. Without one it takes the first that refunds at least `bailoutAtLeastMillions` in `strategy.ts`, $1B. Each strategy's section of the report says how often it took the Bailout and how those Programs ended, from `bailoutReport.ts`. The `playStyle` helper in `src/balance/playStyle.ts` covers the common case, with the choices it can make in `playStyleOptions.ts` and the Missions it builds for its Assets in `assetMissions.ts`, and pays Upkeep as `src/balance/upkeepPlay.ts` says: it keeps every Asset it can pay for, with what is still owed on a Bailout counting towards that as the rules allow, ending the missions of those with the least Service Life left when it can't, or when that frees the money for a launch while it is under its limit of Assets.
